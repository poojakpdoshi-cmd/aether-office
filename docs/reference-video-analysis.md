# Reference Video Analysis

The supplied reference presents a multi-agent orchestration product as a spatial 2D office. Its post-animation interface uses a **soft, retro-system visual language** rather than a dark dashboard: a pale mint-green top-down floor, warm off-white panels, thin dark outlines, compact status labels, muted accents, and restrained shadows. The screen is organized into three practical areas: the illustrated floor on the left, a slim right-side transcript or queue area, and a horizontal employee roster near the bottom.

The reference makes delegation visible. A central orchestrator receives a high-level instruction, distributes subtasks to specialized agents, and invites agents to collaborate. Agents can visibly join a shared table, with speech bubbles or other contextual cues showing collaboration. Employee roster cards use a portrait, a name, and a compact state badge such as `idle`; selecting a person appears to expose a lightweight contextual card rather than replacing the map. The reference also pairs the spatial map with an observability surface that includes terminal output, logs, task status, triggers, memory, and relationship/context views.

The strongest AetherOffice adaptation is a local-first visual state machine: real task-assigned, meeting-started, tool-started, tool-finished, approval-requested, and task-completed events should drive movement and activity. The observed movement model is spatial and readable: employees travel directly through corridors, gather at a shared room, and return to individual workstations. The office map should remain the primary text-free launch surface, while physical objects can open focused detail views for event history, terminal output, monitoring, approvals, and task context. No decorative movement or fabricated activity should be introduced.

The AetherOffice translation will restyle the post-animation control surface as a light office-console queue/command rail, with the existing secured task entry, controlled upload, employee provisioning, encrypted provider-key setup, approval modes, settings, and roster retained. The current 16:9 semi-realistic office art, local-first security model, invisible cabin and laptop targets, and real sandbox inspection remain AetherOffice-specific. Reduced-motion users will receive stable location changes without travel animation.

The reference suggests practical additions: a real-time activity ribbon sourced from the audit log, a meeting route showing invitation and attendance, a task-progress view tied to controlled tool executions, a relationship/delegation graph derived from actual DeepDiscuss rounds, and contextual employee detail cards showing current approved scope. Any new feature must preserve local-only secrets, bounded commands, owner approval, and the existing physical-hotspot navigation model.

## Follow-up Recording Findings

The newer owner recording confirms that the current primary control rail is incorrectly treating a greeting such as `Hello` as a build or DeepDiscuss request. The visible `Starting…` state and provider errors show that the side rail needs to become a manager conversation surface before it can route a message into a real team task. The recording also shows that the office should behave like a scrollable game world rather than a fixed map beside an always-expanded command form. The management area should remain hidden until the owner taps a designated empty-floor hotspot.

The recording additionally shows an unwanted visual artifact during the character movement phase. The correction will remove the affected illustrated overlay from the active employee-motion layer rather than altering the approved office background, so all other rooms and employee art remain intact.
